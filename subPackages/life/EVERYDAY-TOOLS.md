## 随机决定

- 主题 1—60 字，2—20 个非空候选，每项 1—40 字；去除首尾空白后检查重复。选项使用稳定 ID，删除中间行不重用其它输入控件。
- `Math.floor(Math.random() * n)` 按候选位置等概率选择，允许连续两次出现同一结果；没有剔除上次选项或隐藏权重。不用于需要密码学随机性的场景。
- 修改主题/候选即清除旧结果；首次进入不伪造一次已完成的抽选。
- 开关保存一个常用主题。开启后校验有效内容再保存，编辑防抖 250ms，离开页面会提交待保存的有效快照；未填完整时保留上一次有效存档并明确显示未保存原因。
- 关闭开关清除常用主题存档，当前页面输入保留。下次打开仅恢复已明确保存的主题，不默认保存所有输入。

## 行李清单

- 提供周末短途、商务出差、长途旅行三个示例模板，物品按证件与随身、电子设备、衣物与洗漱分组。模板仅提供初始物品，可自行增删，不替代具体目的地的出行要求。
- 新清单全部未勾选，进度从 0 开始；原稿的 3/8、38% 是操作后的展示状态，没有硬编码为用户已装好的物品。
- 勾选数、总数、百分比均来自当前列表；空列表显示 0%，不除以零。分组可折叠，默认展开前两组，衣物组显示首件和总数。
- 每个模板独立保留勾选及自定义物品，切换不覆盖另一个模板。新增物品需选择分组，同组不重复，名称 1—40 字，每个模板最多 100 件。
- 管理模式可移除物品；保留本页最近一次删除以供撤销，切换模板后清除撤销目标。新增 ID 避开撤销暂存项，避免 ID 冲突。
- 使用项目异步存储封装保存全部模板和当前模板索引。读取失败时允许继续整理新清单，但不会自动覆盖未知旧数据；用户点击“重新保存当前清单”后才写入当前快照。写入失败会显示重试入口。

## 存档和验证范围

key 定义在 `config/constants.js`；`utils/everyday-storage.uts` 串行写入并保留本进程最新快照，避免旧异步写请求覆盖新状态。自定义文字经 URI 编码，版本、长度、数量、ID、分组及勾选字段在恢复时校验；不依赖跨端 JSON 对象反序列化的类型差异。存档只在本机，未新增后端接口。

本次只做静态自查：UTS/模板/样式解析，事件、导入、路由、字体及 `git diff --check`；未启动或编译项目，也未执行算法测试。

后续运行验收建议：候选空白/重复/上下限、连续抽选、有效/无效草稿保存、快速输入后返回；清单勾选 3/8 时为 38%、全部打包为 100%、切换模板/重新进入恢复、添加/删除/撤销/空清单、模拟本地读写失败后重试。
