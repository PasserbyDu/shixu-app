## 玩法与本地数据

- 新局在两个不同空位随机生成 2 或 4；每次有效移动后再生成一个方块，概率为 90% 的 2、10% 的 4。
- 四向滑动使用同一压紧与配对算法；相同数字每回合只合并一次，合并出的数字计入当前得分。
- 无效方向或不足 18 逻辑像素的轻点不会生成新方块，不增加得分。单次手势只执行一个方向，多指与取消的手势不执行移动。
- 棋盘手势期间暂停页面纵向滚动，并阻止棋盘触摸移动引起页面滚动；手势结束或取消、页面隐藏时恢复。
- 首次合成 2048 显示成功状态，可以继续挑战更大的数字；无空位且无相邻相同数字时结束。成功与无路可走同时发生时只提供新局。
- 重新开始清空当前分数和棋局，保留历史最佳。确认状态不写入存档，取消后回到原棋局。
- 通过 `utils/storage.uts` 同步读写少量数据，存储 key 在 `config/constants.js`。存档为带版本号的短字符串，包含棋盘、当前分数、已选择继续挑战的标志；最佳分数独立存储。
- 每次有效移动、选择继续、重开、页面隐藏或退出时保存。重新进入恢复有效棋局，不预填设计中的 1,248/4,096 分演示数据。
- 损坏或不合法的存档重新开局并尽量保留有效最高分；初次读取 API 报错时禁止写默认值覆盖尚未读出的旧记录。存储失败仅提示实际发生的失败，游戏仍可进行。
- 纯 UTS 前端实现，无后端、网络请求、新依赖或浏览器 DOM API。

## 静态验收与待运行场景

本次遵照 uniappx 技能只做模板、脚本语法解析，检查路由、依赖、事件和数据流，并执行 `git diff --check`。没有启动项目、编译或运行游戏。
以下是手工逻辑复核后的预期结果，仍需平台运行确认：

| 场景 | 预期 |
| --- | --- |
| `[2,2,2,2]` 向左 | 合并阶段 `[4,4,0,0]`，得 8 分，再在全盘空位生成一个 2/4 |
| `[2,2,4,0]` 向左 | `[4,4,0,0]`，得 4 分；本回合不能继续变为 8 |
| `[4,4,8,8]` 向右 | `[0,0,8,16]`，得 24 分 |
| `[0,2,0,2]` 向左 | `[4,0,0,0]`，得 4 分 |
| 某一列 `[2,0,2,2]` 向上 / 向下 | 该列 `[4,2,0,0]` / `[0,0,2,4]`，得 4 分 |
| 已靠左的 `[2,4,8,16]` 再向左，其它行均不变 | 不生成新方块，不改变得分或存档 |
| 满盘且横向或纵向仍有相同相邻数字 | 仍可继续，不提前结束 |
| 满盘，横向纵向均无相同相邻数字 | 显示本局结束和实际得分 |
| 合并两个 1024 | 加 2048 分，显示成功；继续后不重复弹出成功提示 |
| 成功后继续、离开再进入 | 恢复棋盘、得分、最高分及继续状态 |
| 多指、短点击、触摸取消、滑动中切后台 | 不误移动，不遗留页面滚动锁定 |
| 重新开始，点击继续本局 / 确认重新开始 | 分别为保留棋局 / 两个随机方块且得分归零；最高分保留 |
| 存档长度错误、含 1/负数/非整数方块、得分无效 | 忽略无效存档，安全新局 |
| 本地读取失败或写入失败 | 显示存储提示，不崩溃；读取失败不覆盖旧记录 |

不同设备的触摸滚动拦截、后台恢复和存储权限仍需真机确认。

| 关卡、步数、用时 | 176–246 | 横刀立马、0、00:00，白底圆角条 |
| 棋盘 | 264–636 | 居中的 4×5 棋盘，10 枚棋子；曹操为蓝色 2×2，其余浅蓝 |
| 出口 | 646–672 | 底部中央“↓ 出口 ↓” |
| 操作 | 686–730 | 撤销一步、重新开始 |
| 说明 | 750–800 | 拖动棋子到相邻空位，不可旋转或重叠；经典 4×5 棋盘 · 共 10 枚棋子 |

棋盘宽 584rpx、高 724rpx；单格 128rpx、间距 12rpx、外边距 18rpx。跨两格的棋子尺寸为 268rpx，文字和操作区独立居中，描述字体不小于 20rpx。
全部是实际棋盘元素，没有图片或额外依赖。初始布局与稿件一致（人物名称也按设计保留）：

```text
关羽  曹操  曹操  张飞
关羽  曹操  曹操  张飞
赵云  黄忠  黄忠  马超
赵云   兵    兵   马超
 兵    空    空    兵
```

- 规则和占位计算集中于 `utils/klotski.uts`；按锁定的水平/垂直方向拖动，吸附到合法格子。逐格验证整条路径，不允许越过障碍后落到远处空位。
- 每次成功放置计一步，连续沿同一方向移动两格也计一次拖动。未达到半格的轻触、非法移动、多指或取消手势均不计步。
- 曹操左上角到达 `(列 1, 行 3)`（零起始坐标）时覆盖底部中央出口，立即通关、停止计时，允许撤销回到通关前或重新开始。
- 撤销恢复上次拖动的完整位置，步数减少一；用时不会回退。撤销后可以走新的路径，旧分支不会保留。
- 计时从首次有效移动开始，以实际时间差计算；后台、确认重开期间、通关后停止累计。页面恢复后继续，重开清零。
- 快照包含版本、活动用时、是否开始及完整移动历史。读取时从初始关卡复演每一步，验证边界、碰撞、动作轴和通关状态，拒绝不合法或过长的历史。
- 历史最多 10,000 步，通过项目异步存储封装保存；`utils/klotski-storage.uts` 按队列写入，防止旧快照覆盖新快照，并提供进程内最新快照以支持立即返回。
- 有效移动、撤销、重开、后台和离开时保存；前台计时每 10 秒保存一次。无后端接口，不改变 2048 的棋局或历史最佳。
- 初次读取出错时不会写默认棋局覆盖原记录；保存失败会显示实际错误提示，仍可游戏。重新进入会重试存储能力。
